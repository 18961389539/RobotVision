# RobotVision PLC 集成协议规范（v3）

> 本文档面向 PLC / 上位机集成工程师，描述 RobotVision 视觉系统的 TCP 行协议。
> **v3（2026-08）**：去掉 `TRIGGER` 前缀；触发行直接发**配方名**或**序列号**（`3` / `#3`）。
> 成功应答：`OK,x,y,角度[,...],配方名,目标数,耗时ms` / 失败：`ERR,错误码,消息`。
> 带位姿四段式：`A01,X,Y,RZ` 或 `3,X,Y,RZ`（末端相机 OnArm 工位必须）。

| 文档版本 | 协议版本 | 日期 | 变更 |
|---|---|---|---|
| v3.1 | 请求换行可选 | 2026-08 | 请求有无 `\n`/`\r\n` 均可；无结束符时静默约 100ms 后按完整命令处理。应答仍以 `\n` 结尾 |
| v3 | 序列号触发 + 无 TRIGGER 前缀 | 2026-08 | 触发行简化为配方名/序列号；配方 JSON 增加 serialNumber |
| v2.1 | 1014 缺位姿 + 空闲超时默认永久 | 2026-08 | OnArm 未上报位姿返回 1014；连接默认不断开 |
| v2 | 1012/1013 错误码 + 四段式位姿 | 2026-08 | 新增拍照位姿上报与 OnArm 一致性校验 |
| v1 | 基础命令集 | — | PING / STATUS / TRIGGER,配方名（**v3 起废弃 TRIGGER 前缀**） |

---

## 1. 连接规范

| 项 | 规范 |
|---|---|
| 传输 | TCP，视觉侧为服务端（默认监听 `0.0.0.0:9999`，以现场配置为准） |
| 编码 | ASCII（7-bit，禁止非 ASCII 字符） |
| 帧结尾 | **应答**以 `\n`（LF, 0x0A）结尾。**请求**推荐同样加 `\n`（或 `\r\n`），也可不带结束符：服务端在约 100ms 无后续字节后把已收到内容当作一条完整命令 |
| 大小写 | 命令名不区分大小写（推荐全大写） |
| 数值格式 | ASCII 十进制小数，小数点用 `.`，负号 `-`；**逗号是字段分隔符，数值内不得出现逗号**（欧陆 PLC 默认本地化小数逗号须转换） |
| 连接保活 | 默认**不因空闲断开**（`IdleTimeoutMs=0`）。半开连接由 TCP KeepAlive 探测。可选设 30 天回收僵尸连接。`PING` 仅用于确认进程存活，不再是保活刚需 |
| IP 白名单 | 服务端可配置白名单（精确 IP `192.168.1.10` 或前缀通配 `192.168.*`），不在名单的连接立即断开 |
| 并发连接 | 可配置上限；每个连接串行处理请求（一条请求收到应答后才处理下一条） |

## 2. 命令集总览

| 请求 | 应答 | 用途 |
|---|---|---|
| `PING` | `PONG` | 心跳（仅证明连接存活，不反映视觉忙闲） |
| `STATUS` | `OK,ready\|busy,队列深度,队列上限,最近耗时ms[,连续失败,联锁0\|1]` | 触发前查询管线状态；后两段为过程能力扩展，旧程序可忽略 |
| `CLEARINHIBIT` 或 `CLEARINHIBIT,键`（键=配方名或序列号，如 `3` / `#3`） | `OK,CLEARED` | 解除连续失败联锁（1018）。未知键返回 `ERR,1001,...` |
| `配方名` 或 `序列号`（`3` / `#3`） | 见 §4 | 触发一次检测（不带位姿） |
| `键,X,Y,RZ`（键=配方名或序列号） | 见 §4 | 触发检测并上报拍照位姿（末端相机工位**必须**） |

除 `PING` / `STATUS` / `CLEARINHIBIT` 外，**任意一行均视为触发行**（不再使用 `TRIGGER` 前缀）。
旧格式 `TRIGGER,配方名` 会按段数错误返回 `ERR,1013`（请升级 PLC 程序）。

其他未知单词按配方名解析，通常返回 `ERR,1001`（不是 1000）。

## 3. STATUS 命令（触发前预判）

```
请求:  STATUS\n
应答:  OK,ready,0,4,122\n      ← 空闲：队列 0/4，上次耗时 122ms
应答:  OK,busy,3,4,1009\n      ← 忙：3 个任务排队中（上限 4）
```

**建议**：TRIGGER 前先查 STATUS，`ready` 时再触发可最大限度避免 1009/1010。

## 4. 触发行（原 TRIGGER 命令，v3 起无 TRIGGER 前缀）

### 4.1 两种格式

```
不带位姿:  A01\n          或  3\n   或  #3\n
带位姿:    A01,102.356,-88.412,45.0\n   或  3,102.356,-88.412,45.0\n
                              └X┘   └Y┘    └RZ┘
```

### 4.2 字段定义

| 字段 | 必填 | 单位 | 说明 |
|---|---|---|---|
| `键`（首段） | 是 | — | **配方名**（字母/数字/`_`/`-`）或 **序列号**（正整数，可写 `#3`）；序列号在配方 JSON 的 `serialNumber` 字段配置，全局唯一 |
| `X` | 四段式 | mm | **拍照瞬间**机器人 TCP 的 X 坐标 |
| `Y` | 四段式 | mm | 拍照瞬间 TCP 的 Y 坐标 |
| `RZ` | 四段式 | deg | 拍照瞬间第 4 轴角度 |

### 4.3 何时必须使用 v2 格式

| 相机安装方式 | 是否需要位姿 | 说明 |
|---|---|---|
| 固定机架（相机不动，机器人拿料到视野下） | 不需要 | v1 即可；发 v2 也无害（位姿被忽略） |
| **相机装在机器人末端（随第 4 轴转动）** | **必须** | 未上报位姿返回 **1014**。上报后与档案比对，超容差返回 **1012**，不执行检测 |

**位姿采集时机**：PLC 在发出拍照指令、机器人**完全停止**后读取当前位姿并拼入 TRIGGER。X/Y/RZ 三值必须取自同一时刻的当前位置寄存器。

### 4.4 成功应答

```
OK,102.356,88.412,45.123,-15.004,210.779,132.050,A01,2,1422\n
└┬┘└──────┬──────────────┘└──────────┬──────────┘└┬┘└┬┘└─┬─┘
OK   目标1: x,y,角度            目标2          配方  N  耗时ms
```

| 段 | 含义 | PLC 解析要点 |
|---|---|---|
| 1 | `OK` | 成功标志 |
| 2~(1+3N) | 每个目标：X(mm)、Y(mm)、角度(deg) | **紧跟 OK 顺序读取** N 组三元组；3 位小数；坐标系 = 机器人基坐标系；**角度范围 (-180, 180]**（[0,360) 表示的品牌由 PLC 换算：负角 +360）；若配方启用旋转补偿，角度已含工具零位偏角换算（第 4 轴命令角） |
| 倒数第 3 | 配方名（回显实际执行的配方名） | 审计/对账用；解析坐标可忽略 |
| 倒数第 2 | 目标数 N | 校验三元组个数；0 目标时无坐标段，格式为 `OK,配方名,0,耗时ms` |
| 末段 | 耗时(ms) | 整数 |

**推荐解析顺序**：从尾部读取耗时 → 目标数 N → 配方名，再向前取 3×N 个坐标字段；或顺序读 OK 后连续读 3×N 个浮点，最后用尾部 N 校验。

### 4.5 失败应答

```
ERR,错误码,消息\n
```

消息为可读文本（内部已保证不含逗号/换行）；`1099` 固定为 `INTERNAL_ERROR`（详情只进视觉侧日志）；`1013` 的消息为固定模板（见 §5）。

## 5. 错误码全表与 PLC 处置

| 码 | 含义 | 可立即重试 | PLC 处置建议 |
|---|---|---|---|
| 1000 | 未知命令 | — | 检查报文拼写 |
| 1001 | 配方不存在 / 配方名非法 | 否 | 核对配方名 |
| 1002 | 相机未注册 | 否 | 视觉侧配置问题，联系视觉工程师 |
| 1003 | 取图失败 | **可** | 相机瞬断可重试 1 次；连续失败报修 |
| 1004 | 未标定 / 标定不一致 | 否 | 视觉侧需（重）标定 |
| 1005 | 模型不可用 | 否 | 模型文件缺失/加载失败 |
| 1006 | 光源控制器未注册 | 否 | 视觉侧配置问题 |
| 1007 | 未检出目标 | **可** | 先重试 1~2 次；仍失败检查来料与照明 |
| 1008 | 处理超时（已进入推理） | **谨慎** | 推理已在后台跑完并释放；**先发 STATUS 确认 `ready`**（或等 ≥2×TimeoutMs）再重发 |
| 1009 | 排队超限（busy） | **可** | 管线满载，等 STATUS ready 后再触发 |
| 1010 | 排队超时（未进入推理） | **可** | 请求未被执行即放弃，管线无影响，可立即重试 |
| 1011 | 相机初始化失败 | 否 | pylon 运行库/相机连接问题 |
| **1012** | **拍照位姿不一致** | **核对后可** | 见 §6 |
| **1013** | **TRIGGER 参数格式错误** | 否 | 见下 |
| **1014** | **OnArm 未上报拍照位姿** | 否 | 改为 `配方名,X,Y,RZ` |
| **1015** | **配方被停用（Enabled=false）** | 否 | 通知操作员在视觉界面启用该配方后重试 |
| **1016** | **配方参数/引用校验失败** | 否 | 视觉侧打开配方页修正配置（相机/模型/阈值等） |
| **1017** | **模型/标定哈希与配方钉扎不一致** | 否 | 核对 models/ 与标定目录；配方页重新钉扎哈希并保存 |
| **1018** | **连续失败联锁** | 否（须先排除） | 查光源/来料/相机后发 `CLEARINHIBIT` 或在通信页解除联锁 |
| **1019** | **精修失败** | **谨慎 1 次** | 画面有目标但角度/头尾不过门。查照明与配方精修方法；连续则通知视觉工程师。不要当 1007 漏检 |
| 1099 | 内部错误（含配方文件 IO 故障） | 否 | 记录时间点，联系视觉工程师查日志 |

**1013 的消息模板**（固定 ASCII，PLC 可按消息分流）：

| 消息 | 触发条件 |
|---|---|
| `TRIGGER_ARGUMENT_COUNT` | TRIGGER 参数既不是 1 段也不是 4 段（如 `TRIGGER,A01,1.0`） |
| `MISSING_RECIPE` | 4 段格式中配方名为空 |
| `INVALID_POSE_NUMBER` | X/Y/RZ 不是合法数字（含 `NaN`/`Infinity`/本地化逗号小数） |

> 注：整条 TRIGGER 无任何参数（`TRIGGER\n`）仍返回 `ERR,1001,MISSING_RECIPE`（v1 行为保持不变）。

## 6. 1012 拍照位姿不一致（v2 核心）

### 6.1 触发条件（同时满足）

1. 请求为 4 段格式（PLC 上报了 X,Y,RZ）；
2. 配方工位的外参档案为 **OnArm**（相机装末端）类型；
3. 档案记录了标定拍照位姿；
4. 上报位姿与标定位姿偏差超容差。

比对方式：XY 按**欧氏距离**（mm），RZ 按**归一化角度差**（跨 ±180° 正确处理）。
默认容差 **XY ≤ 0.5mm、RZ ≤ 0.5°**（视觉侧 `appsettings.json` 的 `PoseCheck` 段可调）。

### 6.2 PLC 收到 1012 的处置流程

```
收到 ERR,1012
   │
   ├─ 上报位姿是不是拍照点的真实位姿？
   │     ├─ 否（读错寄存器/未停稳就读）→ 修正采集逻辑后重试
   │     └─ 是 → 拍照点被挪动过（示教修改/程序号切换）
   │            └─ 拍照点是否应该回到标定位置？
   │                  ├─ 是 → 回到标定拍照点后重试
   │                  └─ 否（新拍照点）→ 联系视觉工程师按新位姿重标该工位外参
   │
   └─ 连续 1012 不得进入"带病生产"：位姿不一致时的坐标输出是错的，宁可停线
```

### 6.3 何时不校验（即使发 v2 格式）

- 工位外参为 Fixed（固定机架）类型 → 位姿忽略，正常检测；
- 档案未记录标定位姿（旧档案）→ 放行（视觉侧日志有对应提示）；
- 视觉侧 `PoseCheck:Enabled=false`（过渡期关闭）→ 放行。

### 6.4 已知局限：校验的是"上报值"而非"实际值"

1012 拦截的是 **PLC 报文里的位姿** 与标定档案的偏差。若上位机在机器人**未完全停止**时采样、
或读取了错误的位姿寄存器（报的 ≠ 实际），协议层无法感知——校验形同虚设。
因此对 PLC 侧的硬性要求：

1. 机器人到位信号（in-position）置位后再采样当前位姿寄存器；
2. X/Y/RZ 三值必须取自**同一时刻**的当前位置；
3. **验收测试必须包含错位姿用例**：人为上报偏移位姿（如 X+2mm），确认返回 1012——
   验证整条校验链路真实生效，而非仅靠配置正确。

## 7. 交互时序

```
PLC                                      Vision (TCP Server)
 │                                            │
 │────────── TCP CONNECT ────────────────────>│  白名单校验通过
 │                                            │
 │────────── PING\n ─────────────────────────>│
 │<───────── PONG\n ──────────────────────────│  (心跳，按需)
 │                                            │
 │────────── STATUS\n ───────────────────────>│
 │<───────── OK,ready,0,4,122\n ──────────────│  触发前预判（建议）
 │                                            │
 │── 机器人移动到拍照点，完全停止 ──            │
 │                                            │
 │── A01,102.356,-88.412,45.0\n ─────────────>│  位姿校验(OnArm) → 取图 → 推理 → 坐标变换
 │<─ OK,x1,y1,a1,x2,y2,a2,A01,2,1422\n ───────│
 │                                            │
 │── 机器人按 (x,y,角度) 去取料/贴合 ──         │
```

**超时**：视觉侧单请求默认超时 **90000ms**（可配，启动下限 90s）。PLC 侧接收超时建议设为 **2× 视觉超时**（180s）；
超时后按 1008 的处置流程（先 STATUS 后重试）。

**重试节奏**（总结）：

- 1003 / 1007 / 1009 / 1010 → 延时 200~500ms 直接重试（建议 ≤2 次）；
- 1019 → 可重试 1 次；仍失败按配方/照明处理，不要当 1007 漏检抛料；
- 1008 → 等 STATUS `ready` 再重试；
- 1012 → 按 §6.2 流程排查，禁止盲目重试刷日志；
- 1001/1002/1004/1005/1006/1011/1013/1014/1015/1016/1017/1018 → 停止重试，报警人工处理。

## 8. 集成示例

### 8.1 报文示例（十六进制视角）

```
发送: 54 52 49 47 47 45 52 2C 41 30 31 2C 31 30 32 2E 33 35 36 2C 2D 38 38 2E 34 31 32 2C 34 35 2E 30 0A
      T  R  I  G  G  E  R  ,  A  0  1  ,  1  0  2  .  3  5  6  ,  - 8  8  .  4  1  2  ,  4  5  .  0  \n
接收: 4F 4B 2C 41 30 31 2C 31 2C ... 0A
      O  K  ,  A  0  1  ,  1  , ...
```

### 8.2 ST 伪代码（结构化文本参考）

```iecst
FUNCTION_BLOCK FB_VisionTrigger
VAR
    tcpRecv   : STRING[256];
    poseX, poseY, poseRz : LREAL;      // 拍照点当前位姿（停止后采样）
    frame     : STRING;
    retry     : INT := 0;
END_VAR

// ---- 组包（注意：数值转字符串必须用点号小数，禁止本地化逗号）----
frame := CONCAT('A01,',
                CONCAT(LREAL_TO_STR_DOT(poseX), ',',
                CONCAT(LREAL_TO_STR_DOT(poseY), ',',
                       LREAL_TO_STR_DOT(poseRz))));
tcpSend(frame + CHAR(16#0A));

CASE parseReply(tcpRecv) OF
    'OK':     // 第3段=目标数，随后逐组取 (x,y,角度)
              consumePoses(tcpRecv);
    'ERR':    CASE errorCode OF
                  1012:  // 位姿不一致：核对拍照点，禁止盲目重试
                         alarm('Vision: pose mismatch at photo point');
                  1008:  // 处理超时：等 STATUS ready 再重试
                         waitForReady();
              END_CASE
END_CASE
```

## 9. 兼容性与升级指引

| 阶段 | PLC 行为 | 效果 |
|---|---|---|
| 不升级 | 继续发 `TRIGGER,配方名` | **全部触发失败 1013**。必须改为 `配方名` 或 `配方名,X,Y,RZ` |
| 升级 v2 | 固定机架工位也可发位姿 | 无副作用（位姿被忽略），统一报文格式更省事 |
| 升级 v2 | OnArm 工位必发位姿 | 位姿漂移在触发瞬间被拦截（1012），杜绝错位坐标上线 |

**推荐**：所有工位统一切换 v2 四段式格式（固定机架工位上报当前位姿即可，不参与校验），
PLC 程序只维护一种组包逻辑。
